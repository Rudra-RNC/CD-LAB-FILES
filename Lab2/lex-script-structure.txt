STRUCTURE OF A LEX SPECIFICATION
A lex program has three parts:
definition section
%%
rules section
%%
user defined functions
•

The definition section usual contains, among other things, literal blocks and pattern names.
We shall use the following specification in this section for our experiments :
%option noyywrap
In order for lex to work on greater than 1 input files, we are supposed to define a function
yywrap(). This is not required in our experiments as we shall work with a single input file only.
•

Literal blocks provide a way to initialize variables used in the actions part. These are
marked by the symbols %{ and %}. All the code within these markers are inserted
verbatim in the initial part of the lex.yy.c file.

•

The pattern names are shorthand for defining auxiliary patterns that are used to define
complex patterns. These are inserted after the %{ and %} block and before the start of the %%.

•

The rules section contain a sequence of pattern – action pairs. The set of allowed patterns is
fairly large and discussed later.

•

A rule is a pattern - action pair. The set of pattern action pairs used in lex follows.
