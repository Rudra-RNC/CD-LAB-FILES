Objective : Generate a parser for C expressions using both ambiguous and unambiguous grammars. The
numeric values are of integer and float type. Add semantic actions to the grammar to calculate the value of an
expression and compare the calculated value with gcc. Extend the grammar to handle assignment statements.
Read the handout to understand how a lexer can effectively communicate with its parser in order to perform
semantic actions along with parsing.
P1. The scripts, "exp6.l" and "exp6.y" use an unambiguous grammar to generate expressions in C involving 2
operators and parentheses {+, ‒, (, )}, and terminal {NUM} denoting integer values as operands.
E →E + T | T T → T * F | F
F → (E) | NUM
Note that both the associative and precedence properties of operators are hard coded in the grammar and hence
no special instructions are given in the yacc script. Observe how the actions against the rules use the "$variables" of yacc to perform calculations. Read the handout to understand the association between the grammar
symbols in a rule with the "$-variables".
(a) Generate a parser using the scripts given. Run the parser with the input in file, "ex6inp.txt". Also write a C
program to find out the value of the input expression and validate the output of the C program with that
generated by your parser.
P2. Examine the scripts of ambiguous grammar below that generates the same language as that of P1.
E →E + E | E * E | (E) | NUM
Write a yacc script that uses the above grammar to generate a parser and test its working over the input file,
"ex6inp.txt". In case of difficulty, ask your faculty the way to specify operator properties for an ambiguous
grammar in yacc.

P4. All the problems defined above permitted only integer data type. We now wish to add floating point data
type to the grammar. Since both integer and floating point numbers coexist in the grammar, both rules of the
form, E →NUM | REAL will be present. The $$ variable for lhs E taken 2 different types depending on which
token is sent by the scanner. In yacc there is a single $-variable associated with each grammar symbol (whether
in lhs or in the rhs of a rule). Yacc permits a $-variable to be a union of 2 or more data types in order to meet
such situations. Read the handout on lex-yacc communication for such details. Write lex and yacc scripts to
generate a parser as per the specifications of this problem.
